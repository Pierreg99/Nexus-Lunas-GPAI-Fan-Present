# Five-session freebie plan

A small execution plan for one freebie—not a promise that every project takes five days. Each session is roughly 30–60 minutes; shorten, extend, or split it to fit the people and work. Do not begin expensive production until the riskiest assumption has a sensible test.

## Before session one

Choose one profile in `PROFILES.md`; read `RULES.md`; gather only materials you are allowed to use. Record the available time, tools, intended delivery path, and one person or group who could try the first-use path with consent.

## The plan

| Session | Work | Output | Done when |
| --- | --- | --- | --- |
| 1 — Scope | Use `scope-freebie` and the brief prompt. Name one recipient, one job, one modest outcome, constraints, and the riskiest assumption. | One-page brief; “not in v1” list; up to five acceptance checks. | A human approves the audience, promise, format, scope, and any rights-sensitive inputs. |
| 2 — Check the need | Run one proportionate test: a short task walkthrough, a neutral conversation, or a review of existing support questions. Ask only for information needed. | Anonymized observations; evidence/assumption update; proceed, revise, or pause decision. | The decision follows actual evidence; no invented validation claim or unnecessary personal-data collection. |
| 3 — Make v1 | Use `build-freebie` and the relevant Resource Maker profile. Create only the approved deliverable. | Complete draft; exact open/use instructions; source and attribution notes; file manifest. | A recipient can attempt the core task from the written instructions and the draft meets its acceptance checks. |
| 4 — Review | Run `review-freebie` independently. Test the happy path, one likely failure/empty case, links, keyboard/narrow layout where relevant, privacy, rights, and honest claims. | Severity-ordered findings; recorded test results; fixes and retest notes. | No unresolved blocker. Unverified checks and known limitations are plainly recorded. |
| 5 — Package & decide | Use `package-freebie` with an explicit allow-list. Extract the finished archive into a fresh folder and follow its first-use path. Prepare a no-pressure sharing note. | Verified package; final inventory; short, factual release copy; optional feedback question. | Archive matches the allow-list; no private or unrelated files; local links work; a human explicitly chooses whether and where to share. |

## Release gate

Before sharing, check each item:

- [ ] The actual gift fulfills the exact promise in the approved brief.
- [ ] A first-time recipient can identify the files and first action.
- [ ] The extracted archive contains the expected files, no secrets/private material, and working relative links.
- [ ] Third-party permissions and attributions have been checked for the actual distribution.
- [ ] Known costs, dependencies, data behavior, and limitations are disclosed.
- [ ] No signup, payment, referral, public post, testimonial, or future purchase is required to receive the stated free value.
- [ ] A human owner chooses the release channel and approves the final copy.

## If time runs short

Cut features, not the truthfulness or basic release checks. A finished one-page guide is a better first gift than an unfinished portal. If rights, accuracy, a critical link, or recipient data handling is uncertain, pause that part and be transparent rather than guessing.

## After sharing

If feedback is offered, make participation optional and state how it will be used. Ask one task-based question, such as “Where did you pause when opening the files?” Summarize observations without exposing identifying details; use `PROMPTS.md` prompt 8 to choose at most one evidence-backed next improvement.
