# Rules for a genuinely useful freebie

Use these rules alongside the approved brief. Platform policies and applicable safety requirements still apply. If a request conflicts with a rule or materially changes the agreed audience, promise, cost, rights, or sharing plan, pause and ask the human to resolve it.

## The promise

- Solve one real, clearly described job for one understandable audience.
- Promise only what the delivered files actually do. Distinguish examples, estimates, hypotheses, and verified outcomes.
- Keep the core gift usable without a signup, payment, hidden upsell, or required future purchase. Optional future offers must never be disguised as part of the free gift.
- Make costs, limits, required software, internet access, maintenance dependencies, and known exclusions visible before first use.

## Accuracy and respect

- Use evidence provided for this project. Never fabricate research, testimonials, endorsements, user quotes, metrics, legal rights, affiliations, licenses, or product capabilities.
- Label AI-generated or hypothetical examples as illustrative; check important factual and time-sensitive statements against appropriate sources.
- Write plainly, explain jargon, avoid needless stereotypes, and make assumptions easy to spot and correct.
- Never frame a profile as a real or statistically representative person unless that evidence actually exists.

## Privacy and safe handling

- Ask for the least information needed. Never request passwords, access tokens, private keys, payment details, or confidential material in prompts, demos, or sample forms.
- Disclose storage location and persistence. If data stays in the recipient's browser/device, say so and explain that clearing it can remove it.
- Do not add tracking, analytics, telemetry, remote API calls, or data collection without a specific, disclosed, human-approved need. Prefer an offline/local alternative.
- Treat recipient input as untrusted data. Escape or render it safely; do not execute it or insert it as trusted markup.
- Before sending project material to an AI provider, check that provider's privacy and retention settings. The creator kit itself does not make an external AI session private.

## Accessibility and reliability

- Give an exact, low-friction first-use path and a clear way to continue if an optional feature is unavailable.
- Use descriptive headings, readable contrast and text, explicit form labels, keyboard-operable controls, meaningful link text, and mobile-friendly layouts where relevant.
- Provide a helpful empty state and handle likely invalid input without a crash. State unsupported browsers, formats, or dependencies honestly.
- Test the actual recipient-facing copy, links, and extracted downloads. Mark checks that could not be performed.

## Rights and distribution

- Use original or permitted material; keep attribution and permission records with the project.
- Do not infer a license from a public repository, a free download, or inclusion in this pack. Check the exact source and terms for each third-party asset before redistribution.
- Keep private repository notes, credentials, personal data, drafts not intended for recipients, and unrelated source files out of public bundles.
- A human chooses whether, where, and when to distribute. Do not publish, upload, send messages, spend money, or alter access settings on an assumption of consent.

## Scope and stewardship

- Build the smallest version that satisfies the approved acceptance checks. Put attractive extras in the roadmap, not into version one by stealth.
- Preserve source material and unrelated work. Ask before overwriting, deleting, changing a release destination, or replacing a prior deliverable.
- Keep user data and feedback optional, proportionate, and transparent. Avoid collecting sensitive data or keeping identifiable feedback longer than needed.
- Report what was actually tested, what remains uncertain, and the smallest useful next step. Never call a review a guarantee.
